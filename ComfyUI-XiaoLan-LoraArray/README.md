# 小岚 LoRA 阵列（XiaoLanLoraArray）v7.4

一个只加载 LoRA 到 **MODEL**（不碰 CLIP）的 ComfyUI 节点。**行数不限**，每行可单独设置权重、单独启用/停用、单独写触发词，并输出每行独立的触发词以及合并触发词。

另有一个 **「小岚lora阵列 + 提示词」** 版本：在原节点基础上多一个多行提示词框、一个可增删的**文本列表**（每条可写标题备注 + 正文）、一个只读的「最终文本预览」，以及 `文本输入 / 文本输出` 两个端口。

## 安装 / 更新

把本文件夹放到 `ComfyUI/custom_nodes/` 下。

- **只改了前端 JS**：不用重启 ComfyUI，**Ctrl + Shift + R** 强刷页面即可（扩展文件以 `no-store` 提供）。
- **改了 `nodes.py`**（如 v7.3 增加了 `texts_data` 输入）：**必须重启 ComfyUI 后端**，再刷新页面。
- v7.4（可调分栏）是纯前端改动，**不用重启**，强刷即可。

> 更新顺序很重要：**先重启后端，再刷新页面**。
> 如果反过来，节点会暂时显示成一堆原生文本框，并在控制台红字提示
> `后端缺少 rows_data / prompt_text / texts_data 输入，说明 ComfyUI 还在跑旧版 nodes.py` —— 看到这行就重启后端。

打开旧工作流不用手动改，界面会自动把 `row_1..row_10` 的数据迁移过来；没有文本列表的旧工作流也不会凭空多出条目。

## 节点功能

### 两个版本共有的部分

- **顶部一行**：`[ 总开关 ] [ ＋ 添加 LoRA ]`（提示词版还多一个 `[ ＋ 添加文本 ]`）。
  添加按钮固定在**顶部**而不是节点底部 —— 挂在底部的话每加一行它就往下跑，点完还得追着鼠标找它。
  三个盒子各有各的热区，命中判定严格按 x 落在盒内、y 落在这一行内，**点缝隙不会误触发**。
- **总开关**：关闭时整节点旁路——模型原样透传，触发词也一并清空（提示词与文本列表不受影响）。
- **每行结构**：`[ 开关 ] [ ◀ LoRA 名 ▶ ] [ － 权重 ＋ ] [ 触发词 ] [ ✕ ]`
  - **开关（最左）**：单独启用/停用这一行。**停用后该行不加 LoRA、不输出触发词**，行内容会整体压暗便于辨认。
  - **LoRA 选择**：点胶囊中间弹出下拉，**点一下即选中，无需输入文字**；左右箭头 ◀ ▶ 切换上一个/下一个；菜单按文件夹分组，当前项打 ✓。
  - **权重**：点 `－`/`＋` 每次 ±0.05；按住中间左右拖动可按 0.01/像素 微调，范围 -10~10。
  - **触发词**：点击弹出输入框，Enter 保存、Esc 取消。只填触发词也是一条合法行。
  - **删除（行尾 ✕）**：删除该行，后面行整体上移；只剩一行时点 ✕ 会重置成空行，不会删成 0 行。
- **行数不限**（安全上限 200），超过 30 行时多出一行灰色说明。

### 「小岚lora阵列 + 提示词」额外有的部分

- **文本列表**（LoRA 行下方）：
  - 点顶部 `＋ 添加文本` 增加一条，条目数量不限（上限 50），删光后整块自动收起、节点高度回落。
  - 每条一行：`[ 开关 ] [ 标题/备注 ] [ 正文 ] [ ✕ ]`。
  - **标题是虚线框**，纯粹给你自己看 —— **不参与输出**；**正文**才会拼进合并文本。
  - 点击标题 / 正文弹出输入框编辑；每条左侧开关可临时停用它。
  - 说明行右侧还有 `✕ 删除末条`，用来撤销"手滑多点了两下添加"。
- **提示词框**：原生多行文本框，可换行、可滚动。**节点往下拉，多出来的高度全部给它**（不会被文本列表挤变形）。
- **最终文本预览**（提示词框右侧，只读）：实时显示合并结果、总字数与本次生效的触发词，不用为了确认"触发词到底拼上没有"去执行一次再挂个 Show Text。
- **分栏可以拖**：提示词框和预览框中间有一条分隔条，**按住左右拖**即可调整两边的宽度比；
  **双击**分隔条恢复默认（58%）。比例存在节点属性里，**跟着工作流一起保存**，下次打开还是你拖过的样子。
  两侧都有最小宽度兜底，拖到头也不会把某一侧挤没。
- **端口**：`文本输入`（forceInput，贴在提示词那一行左端，适合接公共前缀/风格词）、`文本输出`（同一行右端，内容与合并输出完全相同，方便就近接线）。

### 输出端口

- **小岚lora阵列**：`model` / `触发词合并输出` / `触发词1` … `触发词30`
  - `触发词合并输出`：汇总所有**已启用**行的触发词，如 `jingjue, wanying`。
- **小岚lora阵列 + 提示词**：`model` / `文本触发词合并输出` / `触发词1` … `触发词30` / `文本输出`

```
文本触发词合并输出 = 文本输入 + 提示词框 + 文本列表各条正文 + 各已启用行的触发词
```

> ⚠ 关于"不限行数"与"30 个独立端口"：
> ComfyUI 的输出端口必须在节点注册时固定，所以"每行一个独立输出"只能给到固定条数。
> **行数本身不受限制**：第 31 行起依旧会加载 LoRA、依旧并入合并输出，只是没有自己的单独端口。

## 连接示例

```
CheckpointLoaderSimple ──[MODEL]──► 小岚lora阵列 + 提示词
                                   ├─ model ─────────► KSampler
                                   ├─ 文本触发词合并输出 ─► CLIP Text Encode
                                   ├─ 文本输出 ───────► 就近接线

```

## 实现说明

### 后端 `nodes.py`

- 输入：`model`、`toggle`(BOOLEAN)、`lora_count`(INT)、`row_1`…`row_10`(STRING)、`rows_data`(STRING)。
- **真正的数据源是 `rows_data`**：一个 JSON 数组，形如
  `[{"lora":"2.5d\\x.safetensors","w":0.8,"t":"jingjue","e":true}, …]`，
  由界面自动维护、行数不限。`lora_count` / `row_1..row_10` 只是为兼容旧工作流保留，
  后端仅在 `rows_data` 为空时才去读它们。
- 只调用 `comfy.sd.load_lora_for_models(model, None, ...)`，不动文本编码器；权重为 0 的行跳过；文件不存在/加载失败会给出中文报错。
- 固定返回 `2 + 30 = 32` 个值，个数与 `RETURN_TYPES` 严格一致，避免节点校验报错。

### 前端 `web/js/lora_array.js`

- 自定义行控件横向布局：`draw(ctx,node,width,y)` + `mouse(e,pos,node)`，`computeSize` 参与布局；
  行控件自身 `options.serialize = false`，数据统一由隐藏控件 `rows_data` 承载（这是行数能无限的前提）。
- LoRA 列表在扩展 `init()` 时**预取一次并缓存**（读 `object_info/LoraLoader` 的 `lora_name`），点开下拉是瞬时的，不会反复请求。
- 下拉用 `LiteGraph.ContextMenu`；下拉是真实 DOM（`.litecontextmenu`）。

## 适配新版前端（1.4x）踩过的坑

1. **控件起始 y 必须固定。** `LGraphNode.arrange()` 会把「端口包围盒底部」当作控件起始 y（`widgets_start_y ?? slotBottom + 2`）。本节点要把触发词端口对齐到每行，绘制时改了端口位置，于是形成正反馈：端口下移 → 控件起始 y 下移 → 行下移 → 端口再下移，**实测每帧涨约 98px**，节点被撑到 1000+ 高、所有控件被画到节点外（看上去一片空白）。
   解决：把 `node.widgets_start_y` 写成固定值（标题高 + 14），`arrange()` 就不再参考端口位置，循环被打断。
2. **`output.pos` 是节点内相对坐标。** `calculateOutputSlotPos()` 会再加上 `node.pos`，所以写绝对坐标会把端口推到节点外面一个节点宽的位置。
3. **`output.hidden` 对输出端口无效。** 绘制输出端口时前端只判断 `isWidgetInputSlot`（输出恒为 false），不看 `hidden`。要「隐去」未用端口有两个坑：
   - 位置必须压到最后一条可见端口上（`output.pos` 是节点内相对坐标），视觉上重叠成一个点；
   - `label` 只能设成**单个空格**。设成空串会被前端回退成 `name`，反而把 `触发词30` 画在最后一行上（踩过，表现为标签重叠）；而且 label 要**每次按当前可见性无条件纠正**，否则一旦被设成空格就再也恢复不了（症状：删行后后面的标签集体消失）。
4. **`widget.mouse()` 只在按住鼠标时才收到 `pointermove`。** 单纯把鼠标移到控件上不会有任何事件派发，所以悬停高亮必须自己在 `document` 上加 `pointermove` 监听（按画布 `ds.scale/offset` + `node.pos` 换算节点内坐标）。这也是"悬停没反应"的根因。
5. **`import { app } from "../../../scripts/app.js"` 有失效风险。** 该文件只是 shim：`export const app = window.comfyAPI.app.app`，在模块求值那一刻取值。若时机偏早会得到 `undefined`，`app.registerExtension` 抛错 → **整个扩展静默失效**（节点表现为一堆原生文本框，正是用户遇到的现象）。现改为 `import * as` + `globalThis.comfyAPI.app.app` / `globalThis.app` 兜底 + 轮询等待。
6. **重绘 API**：本机前端是 `app.canvas.setDirty(fg,bg)`，没有 `setDirtyCanvas`。代码里两种都做了兼容。
7. **隐藏控件仍然会序列化进 prompt。** `graphToPrompt()` 按**控件名**下发，不看 `hidden`（实测：把 `row_1` 设成 `hidden = true` 后依旧出现在 prompt 里），所以可以用隐藏控件当纯状态位（`lora_count`、`rows_data` 就是这么用的）。反过来，`options.serialize === false` 的控件不会进 prompt（实测确认），可以放心用作纯 UI 控件。
8. 隐藏控件不参与布局（`getLayoutWidgets()` 会过滤 `hidden`），所以节点高度只按可见行增长，每行 +30px。
9. 未知 type 的自定义控件会被按 `NODE_WIDGET_HEIGHT + 4 = 24` 估算高度，而带 `computeSize()` 的按 `computeSize()[1] + 4` 估算——高度要自己算准，否则会与前端布局打架。

## 加载时机：四路自愈

本节点界面依赖前端 JS 注入，而"注入时机"是新版前端最容易翻车的地方，所以做了四条互备的升级路径，**只要 JS 被执行过一次，节点最终一定会变成阵列界面**：

| 路径 | 触发时机 | 覆盖场景 |
| --- | --- | --- |
| `beforeRegisterNodeDef` → `onNodeCreated` | 新建节点 | 标准路径 |
| `loadedGraphNode` | 打开工作流时逐节点回调 | 从文件/模板加载 |
| `setup()` 扫描 `app.graph._nodes` | 扩展加载完成 | 扩展晚于工作流加载 |
| `onDrawForeground` 惰性升级 | **任何一次重绘** | 最终兜底 |

升级函数 `upgradeNode()` 是幂等的（`__xiaolan_ready` / `__xiaolan_busy` 双标志），重复调用不会重复插入「＋ 添加 LoRA」按钮。

## 故障排查：还是看到一堆文本框？

说明浏览器里跑的是**旧版 JS**（ComfyUI 只在页面加载时拉取一次扩展）。

1. 在 ComfyUI 页面按 **Ctrl + Shift + R** 强制刷新；还不行就关掉标签页重开 `http://127.0.0.1:8188`。
2. 按 **F12** 打开控制台：
   - 看到蓝色 `[小岚lora阵列] 前端扩展已加载 v7.4` → 新前端已生效，节点会自动变成阵列界面（旧节点也会自愈，不必删掉重建）。
   - 看到红色 `后端缺少 rows_data / prompt_text / texts_data 输入…` → 前端是新的，但**后端还是旧代码，去重启 ComfyUI**。
   - 什么都没看到 → 页面没有加载到这份 JS，再看有没有 `Failed to load module` / `400` 之类的网络报错。
